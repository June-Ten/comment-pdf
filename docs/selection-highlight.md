# PDF 划词评论与高亮

先读「原理」和「关键点」，把整条链路在脑子里立起来。后面的「细分」是把每个关键点拆开，对照到具体函数和边界。改某块行为时，从关键点跳到对应的细分即可。

## 原理

用户在 PDF 正文上拖出一段字，松手后写下评论。刷新、放大、缩小之后，高亮还要盖在同一段字上。

用户打开一份 PDF，在正文上拖出一段文字，松手后在选区旁边写评论。评论和这段文字的位置一起留在这台浏览器里。刷新、放大、缩小、适应宽度之后，高亮仍然盖在同一段字上。右侧列表可以点回这段高亮。右侧还可以按正文查找，匹配到的字另画一套高亮。

页面不使用 PDF.js 自带的查看器工具栏，也不把查看器放进 iframe。PDF.js 只做两件事：

1. 拖动时，用户看见的是浏览器自己的蓝色选区。这时还没有要保存的坐标。
2. 松手时，把选区的每一行换成 PDF 页面坐标，存进评论。蓝色选区立刻清掉。
3. 之后每次把页面画出来（打开、缩放、适应宽度），再用当前缩放把这些 PDF 坐标画回屏幕。

高亮因此不跟着浏览器选区走。缩放和刷新是同一步：坐标不动，变的是画回去时用的缩放。

PDF.js 不负责评论。它只做两件事：把每一页的画面画进 `canvas`，再铺一层透明文字，让浏览器能够划选。人看见的字在画布上，鼠标选中的是透明文字。高亮是夹在两层中间的 SVG，看得见，点击会穿过去。

```
看见的字     canvas          最下面
高亮         svg             中间，不接收鼠标
能划选的字   透明 textLayer   最上面
```

一次渲染会得到这一页的 viewport。画布、透明文字、高亮都问这同一个 viewport：它已经包含当前缩放，以及从“左下角、y 向上”翻到“左上角、y 向下”。存坐标用它的逆变换，画坐标用它的正变换。不要自己用页面宽高做除法。

评论里真正用来定位的是 `anchors`：按页分组的矩形，每个矩形是 PDF 坐标里的左下角和宽高。引用文字和前后文一起存，但定位不读它们。查找不入库，它临时造出同样形状的矩形，画的时候走同一条回路。

## 关键点

1. **看见的和选中的不是同一层。** 画布负责显示，透明文字层负责划选，SVG 只负责画下划线。点在高亮上，事件其实落在文字层，再由页面自己用坐标判断点中了哪条评论。
2. **存 PDF 坐标，不存屏幕坐标。** 一条评论的位置是 `anchors[].rects`，形如 `{ x, y, width, height }`，原点在该页左下角。屏幕上的 `<rect>` 和 `<line>` 每次现算。
3. **换算交给 viewport。** `convertToPdfPoint` 把页内像素变成 PDF 点，`convertToViewportPoint` 反过来。y 轴会翻转，所以两个角转换后谁大谁小不能假定，代码取较小值和绝对宽高。viewport 放在普通 `Map` 里，不能放进 Vue 的响应式对象，否则私有字段会坏。
4. **工具栏上的百分比不是 PDF.js 的 scale。** 页面自己的 `userScale` 为 1 时显示 100%。传给 `getViewport` 的是 `userScale × 96/72`。`96/72` 把 PDF 的“点”换成 CSS 的“像素”（72 点 = 1 英寸，96 像素 = 1 英寸）。
5. **松手才取样，取样后马上清掉浏览器选区。** 拖动过程中不要把选区写成评论。松手后等一帧再读 `getSelection()`，让浏览器先把选区稳定下来。没有拖出文字时，同一次点击改去做高亮命中。
6. **多行选区收成每行一条下划线。** `getClientRects()` 会按行给出很多小框。过小的、几乎盖住整页的丢掉；重叠超过后来者面积 60% 的丢掉；同一行上缝很小的合成一条，并且统一成相同的底边和行高。
7. **点击不打在 SVG 上。** SVG 设置了 `pointer-events: none`。命中是把点击点换回 PDF 坐标，从最新的评论往前，看点是否落在某个矩形里。后写的评论盖住先写的。
8. **查找复用同一套矩形。** 在文字层里找到字符串，做成一个 `Range`，然后调用划词用的 `anchorsFromRange`。查找结果不写入 `localStorage`，关键字清空或重新渲染文字层后整表重算。
9. **评论按文档分开存在这台浏览器里。** 键是 `comment-pdf:` 加上文档 id。没有服务器，高亮也不写进 PDF 文件。换一份 PDF，读的是另一组评论。

下面按这 9 点展开。

## 细分

### 1. 三层各自做什么

每一页是一个 `article.pdf-page`，页码从 1 开始，写在 `data-page` 上。三层都绝对定位、铺满页盒子：

| 从下到上 | 元素 | 作用 |
| --- | --- | --- |
| 画布 | `.canvas-wrap > canvas` | 人看见的页面。鼠标到不了这里 |
| 高亮 | `svg.highlights` | 下划线，选中时再铺半透明底色。`pointer-events: none` |
| 文字层 | `.textLayer` | 透明 `span`。划选和点击都落在这里 |

文字层由 PDF.js 的 `TextLayer` 生成。每个文字块是一个绝对定位的 `span`：位置写成相对页宽、页高的百分比，字号和水平缩放写成 CSS 变量。样式沿用 PDF.js 查看器的规则（`--scale-factor`、`--total-scale-factor`、`--font-height`、`--scale-x`）。少掉这些变量，透明字会和画布错位，划出来的矩形就偏了。

`span` 的文字颜色是透明的，`::selection` 在拖动时给出半透明蓝。松手后蓝色被清掉，留下 SVG 下划线。

创建文字层时：

```js
page.streamTextContent({
  includeMarkedContent: false,
  disableNormalization: true,
})
```

`includeMarkedContent: false` 表示不要再为 PDF 的标记结构包一层节点。打开的话，同一段字会同时出现在父子 `span` 里，选区会给出两套几乎重合的框。`disableNormalization: true` 表示不要改写 Unicode，这样引用和查找读到的字与用户划到的字一致。

扫描件没有文字项，文字层是空的，无法划选。本页没有 OCR。

文字层末尾有一个 `.endOfContent`。平时它被推到页盒子底边之外。按下鼠标时，所在文字层加上 `selecting`，这个空元素盖住整页。浏览器就会允许选区拖过一行的最后一个字，而不是停在最后一个 `span` 上。松手时去掉 `selecting`。它不参与画高亮。

### 2. 坐标怎么存、怎么换

窗口矩形来自 `Range.getClientRects()`：多行就是多个矩形，不是一个包住整段的大框。每个矩形用中心点找到它所属的 `[data-page]`。中心落在页与页的缝里则丢掉。

换成 PDF 矩形的步骤（`clientRectToPdf`）：

1. 用这一页 DOM 的 `getBoundingClientRect()` 得到页盒子左上角。滚动已经含在这个矩形里，不用再加 `scrollTop`。
2. 选区的 `left/top/right/bottom` 减去这个左上角，得到相对该页左上角的像素。
3. 两个角分别调用 `viewport.convertToPdfPoint`。
4. `x`、`y` 取较小值，宽高取绝对值。存下来的 `x, y` 是左下角。

画回去（`pdfRectToViewport`）是逆操作：左下角和右上角调用 `convertToViewportPoint`，再取较小值和绝对宽高。得到的是相对该页左上角的 CSS 像素，和 SVG 的 `viewBox` 是同一套数。

简化例子。设 1 个点等于 1 个 CSS 像素、页面高 200（真实渲染还会乘 `96/72`，方向不变）。页盒子左上角在窗口的 `(80, 40)`。选中一行，窗口矩形左上角 `(200, 120)`，宽 160、高 24。

减去页原点后，相对页左上角是 `(120, 80)` 到 `(280, 104)`。翻到 PDF 坐标：

- x 仍是 120，宽度 160
- 上边缘页内 y = 80，对应 PDF y = 200 − 80 = 120
- 下边缘页内 y = 104，对应 PDF y = 200 − 104 = 96

存下来的是 `{ x: 120, y: 96, width: 160, height: 24 }`。放大之后这个对象不变，变的是画回去时的 viewport。

`PageViewport` 有私有字段，放进 Vue 的 `ref` 会被代理弄坏。所以 viewport 只进普通的 `viewportMap`，键是页码。Vue 用来触发重绘的是 `pageMetrics`：每一页的 `{ width, height }`，等于当时 viewport 的 CSS 宽高。高亮函数看到 `pageMetrics` 变了就重算，换算时再按页码去 `Map` 里取 viewport。

一条评论里和位置有关的部分长这样：

```js
anchors: [
  { page: 1, rects: [ { x, y, width, height }, /* 这一页的每一行 */ ] },
  { page: 2, rects: [ /* 选区跨页时 */ ] }
]
```

同页的多行在同一个 `rects` 里。页码从小到大。另外还存 `quote`（选中文字，连续空白压成一个空格）、`prefix` / `suffix`（前后各最多 20 字）、`body`、`id`、`createdAt`。前后文只保存，不参与定位，界面也不显示。

### 3. userScale 和 viewport 的 scale

`userScale` 是这个页面自己的缩放倍数，初始为 1，范围夹在 0.5 到 3。工具栏百分比是 `Math.round(userScale * 100)`。

真正传给 PDF.js 的是：

```js
page.getViewport({
  scale: userScale * PixelsPerInch.PDF_TO_CSS_UNITS, // 96 / 72
})
```

因此 `userScale === 1` 时工具栏显示 100%，viewport 的 `scale` 约是 1.333。这个 1.333 会写成 CSS 变量 `--scale-factor`，文字层用它算字号。不要把工具栏上的 100% 和 `viewport.scale` 当成同一个数。

两种模式：

- `fit`：适应宽度，也是每次打开文档的初始模式。用第一页在 `userScale = 1` 时的宽度当基准，除以滚动区域的可用宽度（至少按 240 像素算）。后续页更宽时会出现横向滚动，不会每页单独缩小。
- `custom`：点放大乘 1.1，点缩小除以 1.1。之后窗口变宽不再自动改比例，直到再点“适应宽度”。

适应宽度还监听滚动容器尺寸，停 150 毫秒再重画，避免拖动窗口时每一帧都渲染。重画会重建画布和文字层，PDF 矩形不动。

画布位图比 CSS 尺寸更密：`canvas` 的像素宽高是 viewport 尺寸乘 `min(devicePixelRatio, 2)`，CSS 上仍铺满页盒子。这是为了在高分屏上清楚一点。显示缩放超过 200%，或者页盒子的 CSS 取整和位图像素对不齐时，浏览器会把位图再平滑缩放一次，字会发糊。看得见的字是这张位图，不是上面那层透明文字。

### 4. 从按下到发出一条评论

监听在滚动容器上。按下只给所在文字层加上 `selecting`。松手后的分支是：

| 顺序 | 条件 | 结果 |
| --- | --- | --- |
| 1 | 点在评论框 `.composer` 上 | 什么都不做，避免把“发送”当成一次新的划词 |
| 2 | 下一帧读到了有效选区 | 记成草稿，清掉浏览器选区，打开评论框 |
| 3 | 没有选区，但焦点已经在评论框里 | 不关掉正在写的草稿 |
| 4 | 没有选区，点击落在某条评论的矩形里 | 关掉草稿，选中那条评论 |
| 5 | 没有选区，也没点中高亮 | 只关掉草稿，右侧当前选中项不变 |

有效选区还要再排除：选区已折叠（只是点了一下）、去掉空白后没有字、起点不在本页的 `.textLayer` 里。只检查起点。起点在文字层、终点拖出页面时，页外的矩形会因为中心不在任何页里被丢掉。

草稿除了引用、前后文和 `anchors`，还带最后一个窗口矩形 `clientRect`，只用来摆评论框，不写入评论。评论框 `position: fixed`，宽 280 像素，默认在该矩形下方 8 像素；靠右、靠左、靠下会翻到视口内。它不在滚动容器里，所以一滚动，若焦点不在输入框，草稿就关掉，避免框留在已经滚走的选区旁边。Escape 同样取消。

发送要求正文去掉空白后非空。`PdfView` 把 `quote`、`prefix`、`suffix`、`anchors`、`body` 交给 `App.vue`。`App.vue` 补上 `crypto.randomUUID()` 和 ISO 时间，追加到评论数组末尾，并把它设为当前选中。数组一变就写入 `localStorage`。

前后文只取选区第一页的叶子 `span`（内部不再包含 `span` 的那一层）：起点前最多 2 个 span 的末尾 20 字，终点后最多 2 个 span 的开头 20 字。

### 5. 一行上的许多小框怎么收成一条下划线

`anchorsFromRange` 对每个窗口矩形依次过滤：

1. 宽或高小于 2 CSS 像素：丢掉。
2. 中心不在任何页盒子里：丢掉。
3. 宽和高都超过该页 85%：丢掉。这是拖选时浏览器偶发的整页框。只是很长的一行可以接近页宽，所以必须宽和高同时超标才丢。
4. 这一页还没有 viewport：丢掉。
5. 换成 PDF 矩形后，宽或高小于 0.5 点：丢掉。

留下来的按页分组，再做两步。

**去重。** 按原有顺序看。若当前矩形和某个已保留矩形重叠，且重叠面积超过当前矩形自己面积的 60%，丢掉当前这个。先出现的留下。阈值比的是后来者自己的面积，不是两个框的并集：大框被小框盖住一角时，小框不会因此被删。去重只在生成 anchor 时做一次。

**按行对齐再合并小缝。** 两个矩形在 y 方向的重叠长度大于较矮那个高度的一半，算同一行。同一行统一成相同的底边和行高，下划线才在一条水平线上。从左到右，若间隙小于等于 `max(1.5, 行高 × 0.6)` 点，就并成一条；间隙更大则留成同一行上的两段（一行里只选了左右两个词时就是这样）。1.5 点大约 0.5 毫米，用来粘住字距造成的小缝。

例子。两块 `{ x: 10, y: 100, width: 40, height: 12 }` 和 `{ x: 52, y: 101, width: 30, height: 11 }`。垂直重叠够得上同一行，间隙只有 2 点，小于阈值 7.2，合成 `{ x: 10, y: 100, width: 72, height: 12 }`。

画每一笔高亮时还会再跑一次行对齐。已经对齐过的矩形再跑一次结果不变。存储里的旧 JSON 不会在读取时被改写。查找得到矩形后也走 `anchorsFromRange`，所以过滤、去重、合并和划词是同一套。

### 6. 画回屏幕，以及点击如何选中评论

每一页只有一个 SVG。`viewBox` 是 `0 0 页宽 页高`，单位是当前 viewport 的 CSS 像素。还没有这页的 `pageMetrics` 时不画，避免用半初始化的坐标。

绘制顺序是：已有评论、未发送的草稿、查找结果。后画的盖住先画的，所以同一块字上查找的蓝色会压住评论的金色。点击判断不看谁画在上面，只看评论的 PDF 矩形。

每一行是一组：

```html
<g class="comment active" data-comment="评论 id">
  <rect />
  <line />
</g>
```

`<rect>` 默认没有填充。`<line>` 画在矩形底边，就是下划线。草稿的 id 固定是 `"draft"`，始终按选中样式画。查找结果带 `data-match`，不带 `data-comment`。

| 状态 | 样子 |
| --- | --- |
| 普通评论 | 金色下划线 `#e6a100`，没有底色 |
| 选中的评论，以及草稿 | 黄色半透明底，下划线 `#d86b00` |
| 普通查找结果 | 蓝色下划线 `#2f6fed` |
| 当前查找结果 | 蓝色半透明底，下划线 `#1d4ed8` |

点击命中（`commentAtPoint`）只在“这次松手没有形成选区”时进行：点击点换成 PDF 坐标，从评论数组末尾往前测点是否落在矩形内（含边界）。重叠时后写的那条胜出。草稿和查找不参与。没命中则不发 `select`，右侧当前项保持不变。

命中或在右侧点某一条，都会设置 `activeId`，并让 `focusNonce` 加 1。`activeId` 决定谁带选中样式。`focusNonce` 每次点都变，这样连续点同一条也会再次把 `[data-comment="这个 id"]` 滚到视口中间。跨页评论滚到页码较小的那一页上的第一笔。

### 7. 查找

查找框每次输入都更新关键字，不用按回车。关键字变了要重查；文字层重画之后也要重查，因为文本节点在每次渲染时都会被清掉重建。

规则是：

- 去掉首尾空白后为空，结果为空。
- 按页查找，不把多页拼成一个字符串，所以匹配不能跨页。
- `indexOf` 精确匹配，区分大小写，不用正则。找到一处后从匹配结束的位置继续，相邻结果不重叠。
- 用首尾字符做成 `Range`，交给 `anchorsFromRange`。矩形被过滤光的匹配不进入结果。

结果不入库。有结果时把当前项滚到中间。上一项、下一项、点击结果、以及不在评论输入框里时按上下方向键，都会切换当前项并再滚一次。到头之后从另一端绕回。清空关键字后蓝色下划线消失。评论列表仍在匹配列表下面。

### 8. 文档、存储和渲染

默认 PDF 来自 `public`，`docId` 就是它的地址（含 `BASE_URL`，所以 GitHub Pages 的 `/comment-pdf/` 和本地 `/` 各存各的）。上传的文件没有稳定地址，`docId` 用 `file:文件名:字节数:lastModified`。文件改过之后大小或修改时间变了，就会换成另一组评论。非 PDF 会提示“请选择 PDF 文件”，不更换当前文档。

`localStorage` 的键是 `comment-pdf:` 加上 `docId`。值带 `version: 1` 和同样的 `docId`。版本或文档 id 对不上、JSON 损坏、`comments` 不是数组，都当成没有评论。`docVersion` 固定写 1，读取时不检查。没有后端。把原 PDF 拷到另一台机器，看不到这些下划线。

换文档时清掉草稿、选中项和查找，滚动回顶部，并销毁上一份 PDF.js 文档。打开和渲染都带编号：新的一次开始后，旧的异步结果在下一次检查时丢掉，避免两轮同时改同一块画布。某一页渲染失败会停掉这一轮剩下的页，不写入半套页面尺寸。

PDF.js 还需要 cmap、标准字体、wasm、icc。这些文件在 `node_modules/pdfjs-dist` 里，由 `vite.config.js` 在开发和打包时提供到 `/pdfjs/`。缺了它们，中文和部分字体、图像会画不出来，文字层也可能对不齐。

### 9. 现在没有做的事

坐标能对上，是因为再次打开的是同一份 PDF，页面内容没有移动。

- PDF 重新导出或增删页面后，旧页码和坐标可能指到别的内容。前后文不会用来重新定位。
- 高亮是轴对齐矩形。旋转的字按外接矩形铺色，下划线沿矩形底边，不沿字的基线方向。
- 查找是单页内的精确子串。
- 评论框不跟着页面滚动。焦点不在输入框里时，一滚动就关掉未发送的草稿。
- 适应宽度只看第一页。
